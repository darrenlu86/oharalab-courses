# stage2_eda 分析結論報告

資料：`data/raw/{taipei,taichung,kaohsiung}.csv`，Open-Meteo Historical
Weather API（ERA5 再分析網格，非氣象站觀測），2015-01-01~2025-12-31，
每城 4018 天，三城合併 12054 列。以下數字全部取自 `analysis.ipynb`
2026-07-24 的實際 headless 執行輸出（nbclient 驗證 0 error cell），不是
手填估計值。

## 資料清理結果

- 缺值：三城市十個數值欄位全數為 0（`missing_value_report` 實測輸出）。
- 型別：十個欄位全部正確解析為 `float64`/`int64`，無字串殘留。
- 離群值（IQR，k=1.5）：`temperature_2m_max` 144 筆、`precipitation_sum`
  1550 筆、`windspeed_10m_max` 263 筆——全部保留未刪除（降雨右偏分布是
  預期現象，見 README「為什麼這樣設計」）。

## 意外發現：precipitation_sum 與 rain_sum 並非完全相等

相關矩陣熱圖四捨五入顯示 1.00，實際算出來是 0.9999969。追查後發現三城市
12054 筆資料裡有 3 筆兩欄不相等（實測輸出）：

```
        date      city  precipitation_sum  rain_sum
  2016-01-23    taipei               27.9      27.8
  2016-01-24    taipei                5.6       1.6
  2016-01-24  taichung                9.7       8.8
```

三筆全部落在 2016-01-23~24，與台灣 2016 年 1 月那波破紀錄低溫寒流的時間
重疊（當時媒體廣泛報導台灣多處平地出現罕見降雪/凍雨現象）。**這裡只到
「時間吻合、數字方向合理」的程度，CSV 本身沒有天氣現象代碼欄位可以直接
證實是降雪或凍雨造成的落差，本報告不把這個推測當成已證實的結論**，只
如實記錄「兩欄不是完全相等，差異出現在這三筆，且時間點與已知的低溫事件
吻合」。這是分析過程中真的發現的細節，不是預先埋的教學梗。

## 整體結論

1. 三城市的季節與地理差異（北部冬雨、中南部夏雨、高雄冬暖）在 11 年真實
   資料上都得到驗證,不是憑印象的地理課本常識。
2. 「熱」與「熱的次數多」是兩件不同的事：高雄年均溫最穩定溫暖,但極端
   高溫天數遠低於台北——體感悶熱程度不能只看年均溫。
3. 降雨資料右偏分布,不適合用常態分布假設的方法直接篩掉極端值,本階段
   刻意保留所有離群值供後續分析（stage4 建模時再決定怎麼處理)。
4. 11 年樣本不足以判斷氣候尺度的暖化趨勢,本報告主動承認這個方法論限制。
5. 相關矩陣的四捨五入顯示可能掩蓋掉「幾乎但不是完全相等」的細節（本報告
   的 precipitation_sum/rain_sum 案例)，這是一個值得記住的分析習慣提醒。
6. ERA5 再分析網格資料 ≠ 氣象站觀測（見 `docs/DATA_SOURCES.md`),局部
   強對流天氣可能無法被完整捕捉,本報告的降雨相關結論建立在網格估計值上。
