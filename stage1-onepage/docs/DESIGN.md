本文件對應課綱產出要求 3「含桌機/平板/手機呈現的設計說明文件」。

## 1. 三個斷點

| 斷點名稱 | 寬度範圍 | 導覽列 | 商品欄數 | 故事/門市區塊 |
|---|---|---|---|---|
| 手機（mobile） | < 768px | 漢堡選單收合 | 2 欄 | 圖文上下堆疊 |
| 平板（tablet） | 768px–1023px | 橫列展開 | 3 欄 | 圖文左右並排 |
| 桌機（desktop） | ≥ 1024px | 橫列展開 | 4 欄 | 圖文左右並排，容器置中最大寬 1120px |

**為什麼選 768 / 1024 這兩個切點**：768px 對應最常見的平板直向寬度（例如 iPad 直向），1024px 對應筆電/桌機瀏覽器最小可視寬度的通俗慣例值。這兩個數字是業界最通用的兩段切法，不是本專案自創——好處是學員以後接手任何專案，看到 `768`／`1024` 這兩個數字大概就能猜到用途，換算到別的專案也一樣適用，比自創一套切點更容易溝通。

**為什麼是 mobile-first（用 `min-width` 疊加）而不是 desktop-first（用 `max-width` 疊加）**：CSS 裡沒有包在任何 media query 裡的規則，就是「手機版」的預設值；`min-width` 只在螢幕變寬時「加規則」。好處是任何極端窄的裝置（比 768px 還窄的舊手機、摺疊機）都能拿到堪用的基礎樣式；如果反過來用 desktop-first，極端窄裝置會直接套用「桌機樣式硬擠進小螢幕」，通常會爆版。詳細程式碼見 [`CODE_GUIDE.md` 2.4 節](CODE_GUIDE.md)。

**三裝置間最關鍵的差異，一句話總結**：手機是「單欄由上而下捲動」，平板/桌機把「原本上下堆疊、彼此有關聯的兩塊內容」（如 hero 文字＋插圖、故事插圖＋文字、門市文字＋地圖）改成左右並排，商品卡的欄數則跟著可視寬度從 2→3→4 遞增——這是 grid 佈局「隨容器寬度重新分配欄數」的典型用法，不需要為每個斷點另外寫版面邏輯。

## 3. 色彩 tokens 與對比實測

色彩定義在 `css/style.css:10-19`（CSS 自訂屬性）。以下對比比率用 WCAG 2.1 相對亮度公式實際計算（`python3` 腳本執行結果，非估算）：

| 前景 | 背景 | 對比比率 | 是否達 AA 4.5:1（一般文字） |
|---|---|---|---|
| `--color-text` #2b211a | `--color-bg` #faf6f0 | 14.61 | 通過 |
| `--color-text` #2b211a | `--color-surface` #ffffff | 15.73 | 通過 |
| `--color-primary` #4b3324（標題/主按鈕文字底色） | `--color-bg` #faf6f0 | 10.85 | 通過 |
| `--color-primary-light` #6b4a33 | `--color-bg` #faf6f0 | 7.35 | 通過 |
| `--color-accent` #9c5b2b（連結/強調） | `--color-bg` #faf6f0 | 4.94 | 通過（貼近門檻，未來若要再調色需重新驗證） |
| `--color-success` #2e6b40 | `--color-bg` #faf6f0 | 5.92 | 通過 |
| `--color-error` #a13333 | `--color-bg` #faf6f0 | 6.42 | 通過 |
| 白字 #ffffff | `--color-primary` #4b3324（主按鈕背景） | 11.68 | 通過 |
| 白字 #ffffff | `--color-accent` #9c5b2b | 5.32 | 通過 |

**結論**：master spec 指定的全部色彩組合都已達 WCAG AA 4.5:1，不需要加深任何顏色。`--color-accent` 是最接近門檻的一組（4.94），如果之後任何一階段想再調整這個顏色，務必重新跑一次對比計算，不要憑肉眼判斷「看起來夠深」。

## 4. 字體 tokens

```css
--font-sans: -apple-system, BlinkMacSystemFont, "Noto Sans TC", "PingFang TC",
  "Microsoft JhengHei", sans-serif;
```

**為什麼用 system font stack、不載 Google Fonts 之類的 webfont**：本階段的硬性要求是零依賴、零 CDN，`file://` 直接打開也要能正常顯示——如果引入外部字型檔，離線環境或封鎖外部請求的環境會整頁沒有中文字型可用（或載入變慢）。System font stack 直接使用作業系統內建字型（macOS 用 `-apple-system`/`PingFang TC`、Windows 用 `Microsoft JhengHei`），保證任何情況下都有可用的中文字型可以顯示。

| 用途 | 字級 | 對應規則 |
|---|---|---|
| H1（品牌名稱） | 手機 2rem／桌機 2.75rem | `css/style.css:78-80`、`633-635` |
| H2（區塊標題） | 1.5rem | `css/style.css:82-84` |
| H3（卡片標題/FAQ 問題） | 1.15rem | `css/style.css:86-88` |
| 內文 | 1rem（跟隨瀏覽器預設 16px，用 rem 讓使用者調整瀏覽器字級設定時整站跟著縮放） | `css/style.css:57` |

## 5. a11y 檢查清單（已落實項目）

- 對比：見第 3 節，全部通過 AA 4.5:1。
- 鍵盤操作：漢堡選單按鈕、accordion 按鈕都是原生 `<button>`，天生可以用 Tab 移到、Enter/Space 觸發，不需要額外寫鍵盤事件處理。
- Focus 樣式：`css/style.css:101-104` 用 `:focus-visible` 統一換成品牌色外框，取代瀏覽器預設（不是用 `outline: none` 隱藏焦點）。
- `aria-expanded`：漢堡選單按鈕（`index.html:26`）與每個 accordion 按鈕（`index.html:199` 等 5 處）都有，並由 JS 即時更新（`js/main.js:24`、`js/main.js:106`）。
- Skip link：`index.html:14` 提供「跳到主要內容」，讓鍵盤使用者不用每次都從導覽列一格一格 Tab 過去。

**未實測項目（誠實聲明）**：本文件的對比比率是用程式精確計算的實測數據；鍵盤操作與 `aria-expanded` 的正確性則是依 WAI-ARIA 慣用模式撰寫並人工檢查程式邏輯，**未使用螢幕閱讀器（如 VoiceOver、NVDA）實機朗讀測試**——這需要另外安排的人工測試步驟，非本次建置範圍內完成，如果要正式上線建議至少用 macOS 內建的 VoiceOver（Cmd+F5）走一次全站。
