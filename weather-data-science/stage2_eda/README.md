# stage2_eda — 台灣三城市 11 年天氣 EDA（AI-8）

## 這一關在教什麼

拿到一份幾千列的表格資料,怎麼在動手建模之前先把它「看懂」：有沒有缺值、
型別對不對、有沒有需要留意的極端值,然後用圖表把資料裡的規律（季節性、
城市差異、趨勢)講成一個故事。EDA（探索性資料分析）不是走個過場,而是
後面所有建模決策（stage4/5 要不要做特徵工程、要不要處理離群值）的依據。

## 你會學到

- pandas 的資料清理三件事：缺值統計、型別檢查、離群值偵測（IQR 方法),
  以及**為什麼右偏分布的資料不能無腦套用「刪除離群值」**。
- 怎麼用 `groupby` + `pivot` 把長格式資料轉成方便畫圖的寬格式（月份 x
  城市)。
- 至少 6 種圖表類型的選擇邏輯：折線圖（週期/趨勢)、箱型圖（分布比較)、
  分組長條圖（類別比較)、熱圖（相關矩陣)。
- matplotlib 中文顯示的坑（字型設定,見 `common/fonts.py`)。
- 為什麼「四捨五入顯示的數字」可能掩蓋掉資料裡的細節（本階段有一個真實
  案例：相關矩陣顯示 1.00,但實際不是恰好 1.0)。

## 逐步教學

### 第一步：為什麼邏輯要抽到 `weather_eda.py`

`analysis.ipynb` 裡完全沒有資料處理的實作細節,只有 `from
stage2_eda.weather_eda import *` 然後呼叫函式。原因：notebook 很難寫
單元測試（要嘛整份 headless 跑一次很慢,要嘛沒人測),把邏輯抽成普通
Python 函式之後,`tests/test_stage2_eda.py` 可以在 0.7 秒內測完 21 個
案例,notebook 則專心做它最擅長的事——串成一個可以逐格閱讀的分析敘事。

### 第二步：清理階段的關鍵決定——不刪除離群值

打開 `weather_eda.py` 的 `clean_data()`,你會看到它只回報離群值數量,
不會動任何一列資料。這是刻意的：本課程的「離群值」多半是真實的極端天氣
（颱風、梅雨鋒面帶來的暴雨),刪掉會讓分析失真。這跟很多入門教材「看到
離群值就用 `df[df[col] < upper_bound]` 濾掉」的直覺做法不一樣,notebook
第一節會具體示範為什麼（降雨量的右偏分布特性)。

### 第三步：六張圖怎麼選出來的

每張圖對應一個具體問題：「季節性怎麼變化」（圖一)、「城市之間差多少」
（圖二)、「降雨的地理差異」（圖三)、「極端事件多不多」（圖四)、「有沒有
長期趨勢」（圖五)、「變數之間怎麼互相關聯」（圖六)。畫圖前先問「我想
回答什麼問題」,再決定圖表類型,而不是反過來想「這種資料該畫什麼圖」。

### 第四步：一個真實的資料細節案例

跑到 notebook 圖六那一節,你會看到一格特別的程式碼把
`precipitation_sum != rain_sum` 的列挑出來——這是分析途中真的發現的
現象（見下方「注意」),不是預先安排的教學橋段。這個案例示範了「相關矩陣
上看起來是 1.00 的東西,不代表真的完全相等」,值得養成「四捨五入的顯示
數字要保持懷疑」的習慣。

## 為什麼這樣設計

**為什麼相關矩陣要合併三城市計算,而不是各城市分開算？** 本階段的目的是
看變數之間（例如溫度與輻射）的關聯性,這個物理關係在三個城市理論上應該
相似,合併計算可以拿到更穩定的估計（12054 筆 vs 各城市 4018 筆)。如果你
想看「城市間的相關性是否不同」,那是另一個問題,延伸挑戰有提到。

**為什麼極端事件盤點只列「天數」而不列「總降雨量」？** 因為教學重點是
「這種事件發生頻率高不高」,而不是「總雨量有多少」——後者受季節性降雨
（例如梅雨）主導,會蓋掉「極端單一事件」這個訊號,兩者是不同的問題,合併
在一張圖裡反而看不清楚任何一個。

## 注意（常見錯誤 / 踩坑紀錄）

- **相關矩陣顯示 1.00 不代表兩欄完全相等**：`precipitation_sum` 與
  `rain_sum` 熱圖上顯示 1.00,但實際係數是 0.9999969（見 notebook 圖六
  解讀)。查下去才發現三城市 12054 筆資料裡有 3 筆兩欄不相等，全部落在
  2016-01-23~24——跟台灣 2016 年 1 月那波破紀錄低溫寒流的時間重疊。這是
  真實分析過程中發現的細節,不是刻意植入的教學梗,寫在這裡提醒你：畫熱圖
  只看到兩位小數,想確認「是不是真的完全相等」要自己再查一次原始數字。
- **matplotlib 中文字型沒設定會變方框**：`weather_eda.py` 的
  `_new_figure()` 每次都呼叫 `common.fonts.setup_chinese_font()`,如果你
  另外寫程式畫圖忘記呼叫這個函式,中文標題會變成一格一格的方框（在沒有
  候選字型的環境下即使呼叫了也一樣會方框,這時候看終端機警告訊息)。
- **notebook 的 repo 根目錄推導**：第一個 code cell 用「往上找
  `requirements.txt`」的方式判斷 repo 根目錄,而不是猜
  `Path.cwd()` 的名稱——這裡曾經真的踩過坑（第一版邏輯猜錯,圖表存到
  repo 外面去了,見 `report.md` 的「踩坑紀錄」)，現在改成跟
  `common/paths.py` 一致的邏輯（往上找已知檔案),兩者互相 assert 一致。
